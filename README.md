# 大阪自由行 2027

手机优先，奶油白与森林绿；2027 年 1 月 10–17 日，五人共用的旅行手册。

## 共用密码

打开网站只需一个共用密码，无需邮箱、注册或个人账号。密码正确后才会下载行程，浏览器记住解锁状态；服务端解锁凭证有效期为 180 天。密码明文只在验证请求中传给云端，不写入浏览器存储、仓库或版本记录。

首次设置必须使用单独交付的一次性设置链接，不能由普通访客抢先设密码。链接用完即失效，只保存哈希，片段参数在页面读取后立即从地址栏清除。请只把设置后的共用密码给同行旅伴。更换密码需要原密码，会让其他联网设备重新解锁。

分享密码的人拥有相同的查看、编辑、恢复与更换密码权限。版本记录显示修改时间与内容，不显示个人身份。没有个人账号、角色分工或按人追踪。

## 保留的功能

- 按日期浏览、搜索、待确认筛选、地图导航、添加与编辑安排。
- 五人在线同步（每 15 秒检查一次）、离线编辑、网络恢复后上传。
- 按条目检查版本、提示并发冲突、保留和恢复版本。
- PWA 主屏幕安装、静态页面离线缓存、JSON 导入导出。
- 换密码、手动锁定与清除本机缓存。

地图不离线缓存。首次解锁需联网；已解锁设备可离线读取缓存和编辑。离线设备无法即时得知密码已更换，恢复联网后会重新验证。手动锁定会清除本机行程和未同步修改，操作前请导出备份。

## 云端结构

`supabase/functions/shared-trip` 是唯一的行程入口，使用共用密码和随机解锁凭证自行认证，因此部署时 `verify_jwt=false`。数据库只保存 bcrypt 密码哈希、凭证摘要、有效期和短期网络限流摘要，不为同行者创建个人账号。

Edge Function 用运行环境中的后端密钥调用仅 `service_role` 可执行的 RPC。优先读取 `SUPABASE_SECRET_KEYS.default`，兼容旧的运行环境变量。任何后端密钥均不能进入客户端、源码或日志。公开 `config.js` 只包含项目 URL 与 publishable key。

对每次数据请求验证凭证。错误密码不会返回行程；历史接口不返回旧账号作者字段。修改仍用操作 UUID、预计版本、原子写入和不可变版本记录。旧的邮箱账号在首次设置共用密码的同一事务内失去行程表与修改 RPC 的直接权限，不删除现有行程。

密码尝试有服务端限制：单网络每 10 分钟最多 10 次、全项目每 10 分钟最多 120 次。浏览器显示服务端返回的等待时间。CORS 仅允许实际 GitHub Pages 的源；CORS 之外仍由共用密码与凭证保护。

## 部署顺序

已有项目迁移：先应用 `supabase/shared_gate.sql`，再部署 Edge Function，再发布新静态页面；最后为创建者生成一次性设置链接。

全新项目：先按顺序执行 `supabase/schema.sql`、`supabase/harden.sql`、`supabase/shared_gate.sql`，随后部署 Edge Function。前两份脚本保留为旧版本建表迁移记录，最终共用入口不依赖个人账号。

一次性设置秘密应在客户端以安全随机数生成，数据库仅保存 SHA-256 摘要与过期时间；不要把实际设置秘密、密码或解锁凭证加入仓库。未设置密码时，普通网站入口不提供创建密码的权限。

GitHub Pages：Settings → Pages → Deploy from a branch → main → /(root)。站点外壳公开，行程内容由云端密码验证保护。

## 行程来源与备份

用户提供的六页最新版 Wanderlog PDF 已导入私人数据库。私人 PDF、行程 JSON 与迁移前备份不进入公开仓库。票价、航班号、营业时间、休馆信息和预约均以最终核实为准；导入安排默认待确认。

## 待确认、地图与记账

待确认总览汇总全部日期，优先显示备注中的明确日期风险，可筛选日期并编辑原安排。旧笔记归档区不用于风险识别；处理风险后同时更新状态和当前备注。

地图路线沿用每日时间排序，提供公共交通／步行、当前位置出发、上一站到这里。每项可保存完整地址以修正同名地点。Google Maps URL 不需要付费 API；地图与实时交通需要网络。候选地点全部保留，不自动优化或承诺通行时间。

五人账本支持固定五个成员编号、自定义昵称、JPY 整数与 MYR 分、按选中成员均分、已发生还款、余额和结算建议、编辑删除及 CSV 导出。两币种分别结算，不自动换汇；余数依固定成员编号分配。还款是记录，不执行支付。账目通过保留的 `ledger-` 编号与 `【五人账本 v1】` 备注格式存入现有私人行程入口，因此复用离线队列、冲突处理、导出备份和版本恢复，无需新增公开数据库权限。昵称不是登录身份。包括行程在内共有500条记录的现有限额。

## 检查

运行 `node --test tests/*.test.js`。检查包括：无凭证拒绝访问、一次性设置、错误密码、凭证过期、换密码后旧请求失效、请求体上限、跨源拒绝、离线解锁缓存、输入校验、版本冲突与离线队列。数据库还需在事务回滚的测试中验证密码哈希、设置秘密消费、旧账号权限撤销、共享修改与换密码失效。

本机开发用 HTTP 服务；不要双击 HTML。生产 CORS 仅允许 GitHub Pages，开发时可使用测试接口。真实手机与多人同步仍需发布后实测。
