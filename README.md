# 大阪自由行 2027

手机优先，奶油白与森林绿。日期：2027 年 1 月 10–17 日；五人共同编辑。

## 第一版包含

- 每日行程、简体中文与当地名称、搜索、状态筛选、地图导航。
- 添加、修改、删除安排，导入与导出 JSON。
- PWA 安装与离线缓存；本机修改持久保存。
- Supabase 邮件登录、最多五人的成员名单、行级访问控制。
- 在线每 15 秒同步一次；离线修改在重连后上传。
- 每条安排采用版本检查；冲突会显示两份内容，由成员选择。
- 本机与云端版本记录，恢复会创建新版本；云端页面显示最近 100 条记录。

## 启用 GitHub Pages

仓库 Settings → Pages → Build and deployment：

1. Source 选择 **Deploy from a branch**。
2. Branch 选择 **main**，目录选 **/(root)**，点击 Save。
3. 等待 Pages 部署完成。

预期地址为 https://wei304.github.io/osaka-2027/ ，以 GitHub 实际部署结果为准。

## 启用五人同步

1. 新建 Supabase 项目，打开 SQL Editor，先执行 `supabase/schema.sql`，再执行一次 `supabase/harden.sql`。后者将需要较高权限的函数移入非公开 schema。
2. 在 Table Editor 的 `trip_members` 表加入五人的小写邮箱；`trip_id` 均填 `osaka-2027`。可先只加自己测试，再加入其他人。请勿将邮箱写入此公开仓库。
3. Authentication → URL Configuration：Site URL 填 `https://wei304.github.io/osaka-2027/`，Redirect URLs 也加入这一完整地址。
4. 确认 Email 登录开启，允许新用户注册，保持邮件验证开启。新用户需要先完成邮件验证；只有成员名单中的邮箱能读写旅行内容。邮件发送限额以你的 Supabase 配置为准。
5. 项目设置的 API / API Keys 页面复制 Project URL 与公开 publishable key（或 legacy anon key）。
6. 在手册“同行与同步”保存这两个值，用成员邮箱发送登录邮件。点击链接回到手册。
7. 首位成员登录后，导入私人行程 JSON，等待所有修改同步完成。其他成员填写同一项目 URL 与公开 key，登录后会下载同一份手册。

**不需要，也不要将 service_role、secret key 或数据库密码填入手册。** 公开密钥只标识项目；成员权限由数据库 RLS 与登录邮箱控制。成员名单仅项目管理员可修改，旅伴不能自行加人。

## 最新行程资料

使用用户提供的六页 Wanderlog PDF。私人导入文件单独交付，包含每日地点、原资料餐饮备选、航班、住宿、和服报价与待确认事项。PDF 与私人 JSON 不进入公开 GitHub 仓库。打开手册 → 同行与同步 → 导入行程 JSON。

所有导入安排默认待确认，表示尚未独立复核。报价、航班号、休馆信息、末班车、行程时间和交通方式均须复核；PDF 未标示已预订，不能视为已预订。

## 本机使用与备份

需要 HTTP 或 HTTPS。开发时 `python -m http.server 8080`，访问 `http://localhost:8080`。不要直接双击 HTML 文件。

首次联网打开会缓存手册文件。地图、登录与同步需联网。iPhone 可使用 Safari 的“分享 → 添加到主屏幕”；支持安装提示的 Android 浏览器会显示安装按钮。缓存不包含地图、第三方页面或 PDF。

修改保存在此浏览器的 localStorage。浏览器清理数据或私人浏览可能移除缓存；请定期导出。退出登录会清除本机行程，未同步修改需先导出。当前版本建议每台设备仅开一个编辑页面。

同一安排的并发修改不会静默覆盖。成员需在“同行与同步”选择保留云端，或用本机内容重新提交。删除使用保留版本的软删除。恢复旧版本会重新提交并接受同样的冲突检查。

线上同步依赖 Supabase 配置。未配置时页面明确显示“本机模式”；不会假装多人同步成功。

## 验证

`node --test tests/*.test.js` 检查输入验证、离线队列、冲突前的数据合并及操作完成后的版本推进。部署前请用两个成员账户验证 RLS、同条安排并发编辑与离线重连。数据库脚本需在你的 Supabase 项目实际运行后才能验证服务端行为。

## 更省事的登录

常用登录改为邮箱与密码。已登录的成员可在“同行与同步 → 设置 / 修改登录密码”自行设置至少 10 位密码。以后在另一设备直接用邮箱与密码登录。首次使用或忘记密码可展开“首次使用 / 忘记密码”，发送一次邮件链接后设置密码。邮件发送仍受服务端限额约束。

网站自动保留登录会话，并记住上次登录邮箱；网站不会保存密码明文。浏览器可自行保存密码。新密码仅发送到 Supabase Auth，设置界面成功后清空密码输入框。高级项目连接参数默认收起。账号登录后的旅行权限仍由原五人名单与 RLS 控制。

密码登录会先验证旅行成员身份再保存会话。测试使用模拟接口检查请求、权限拒绝、登录失败、会话续期与密码更新；真实账号的首次密码设置与登录需由账号本人完成验证。
